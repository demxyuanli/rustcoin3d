  简短回答：技术上可行，但工程量巨大，不建议直接全量移植。

  Coin3D 仓库规模

  ┌────────┬─────────────────────────────────────────────────┐
  │  指标  │                      数据                       │
  ├────────┼─────────────────────────────────────────────────┤
  │ 语言   │ C++ 14.7MB + C 1.2MB                            │
  ├────────┼─────────────────────────────────────────────────┤
  │ 代码量 │ 约 40 万+ 行                                    │
  ├────────┼─────────────────────────────────────────────────┤
  │ 文件数 │ 1500+ 源文件                                    │
  ├────────┼─────────────────────────────────────────────────┤
  │ 历史   │ 1995 年起，已迭代 25+ 年                        │
  ├────────┼─────────────────────────────────────────────────┤
  │ 依赖   │ OpenGL, OpenAL, FreeType, SpiderMonkey, zlib 等 │
  └────────┴─────────────────────────────────────────────────┘

  主要挑战

  1. 体量巨大 — 40 万行 C++ 直接翻译为 Rust 是数人年的工作量
  2. 深度面向对象设计 — Coin3D 大量使用继承、虚函数、多态（Open Inventor
  场景图节点体系），需要重新设计为 Rust 的 trait + enum 模式
  3. OpenGL 深度耦合 — 渲染管线与 OpenGL 状态机紧密绑定，而现代 Rust
  生态更倾向于 wgpu/vulkan 等新一代 API
  4. VRML97 / SpiderMonkey — JS 引擎嵌入、VRML 解析等子系统各自复杂

  建议的可行路径

  ┌─────────────────┬──────────────────────────────┬────────────────────────┐
  │      路径       │             优点             │          缺点          │
  ├─────────────────┼──────────────────────────────┼────────────────────────┤
  │ A. FFI 封装     │                              │                        │
  │ (Rust 封装 C++  │ 快速可用，工作量最小         │ 仍依赖 C++ 运行时      │
  │ 库)             │                              │                        │
  ├─────────────────┼──────────────────────────────┼────────────────────────┤
  │ B. 分层渐进移植 │ 先移植核心场景图，再逐步扩展 │ 需要设计好架构边界     │
  ├─────────────────┼──────────────────────────────┼────────────────────────┤
  │ C.              │ 可用现代 Rust 图形生态       │                        │
  │ 参考实现，全新  │ (wgpu, egui)                 │ 工作量最大，但结果最好 │
  │ Rust 设计       │                              │                        │
  └─────────────────┴──────────────────────────────┴────────────────────────┘

  如果你目标是学习和理解 3D 渲染，路径 C 参考其设计理念用 Rust
  重写核心部分是很好的选择。

  如果你目标是实际使用 Coin3D 的功能，路径 A (FFI 绑定) 最务实。

  你打算走哪个方向？我可以帮你规划具体的实施方案。

     rustcoin3d — Rust 3D Scene Graph Engine Implementation Plan

     Context

     Coin3D (https://github.com/coin3d/coin) is a ~400K LOC C++ OpenGL scene
     graph engine implementing the SGI Open Inventor 2.1 API. The goal is to
     build a new Rust 3D rendering engine inspired by its architecture but using
      modern Rust idioms and the current Rust graphics ecosystem (wgpu, glam,
     winit). No C++ code is directly ported — this is a clean-room Rust design.

     Tech Stack

     │     Layer      │   Crate   │ Version │
     ├────────────────┼───────────┼─────────┤

     ├────────────────┼───────────┼─────────┤
     │ Window         │ winit     │ 0.30    │
     ├────────────────┼───────────┼─────────┤

     ├────────────────┼───────────┼─────────┤

     Core Architecture

     Node storage: SlotMap arena — nodes stored in SlotMap<NodeId, NodeEntry>,
     referenced by generational ID. No Rc<RefCell<>>. Cache-friendly, safe
     against use-after-free.

     Node types: NodeData enum for built-in types (zero-cost dispatch) + Box<dyn
      CustomNode> escape hatch for extensibility.

     Fields: FieldMap (SlotMap<FieldId, FieldEntry>) with dirty flags and
     connection support. Centralized in SceneGraph to avoid borrow checker
     issues during traversal.

     Actions: Trait-based visitor. match on NodeData inside each action's
     traversal. State/Element stack for render state accumulation.

     SceneGraph {
       nodes: SlotMap<NodeId, NodeEntry>,
       fields: FieldMap,
       roots: Vec<NodeId>,
     }

     rustcoin3d CAD Refactoring Plan

     Context

     rustcoin3d 已完成 4 阶段原型（场景图 + wgpu 渲染 + 拾取 + 动画 + .iv
     I/O），但架构面向游戏场景。用户需要将其重构为 CAD 三维模型可视化引擎，核心
     需求：线框/实体/隐藏线显示模式、面/边/顶点级拾取、剖面切割、测量标注、支持
     100 万+ 三角面的大模型。

     三阶段重构

     Phase A: 核心渲染重构（线框/实体/边线 + 性能）

     A1. 新建 rc3d-mesh crate — 拓扑感知的三角网格
     - TriangleMesh struct：positions, normals, faces(含邻接面),
     edges(含共享面), edge_map
     - EdgeKey(packed u64), FaceId(u32), EdgeId(u32) 类型
     - 方法：from_tris(), compute_face_normals(), compute_vertex_normals(),
     boundary_edges(), silhouette_edges(view_dir), edge_line_indices(),
     phong_buffers()
     - 从 render_action.rs 移入 tessellate_cube/sphere/cone/cylinder，返回
     TriangleMesh
     - 新建文件：crates/rc3d-mesh/{Cargo.toml, src/{lib.rs, triangle_mesh.rs, 
     topology.rs, tessellate.rs}}

     A2. GPU 资源管理 — 缓冲区跨帧复用
     - GpuMesh：持久化的 vertex/index/edge_buffer，generation 计数器
     - GpuResourceManager：SlotMap<MeshId,
     GpuMesh>，upload_mesh/invalidate/remove
     - GpuUniformPool：单个大 buffer + dynamic offset，每帧 reset
     - 新建文件：crates/rc3d-render/src/gpu_resource.rs
     - 修改：renderer.rs — 加入 GpuResourceManager

     A3. 多管线渲染 — 实体/线框/边线/选中高亮
     - PipelineSet：5 个 wgpu::RenderPipeline（solid/wireframe/edge_overlay/sele
     ction_fill/selection_edge）
     - 新 shader：flat_color.wgsl（MVP + 纯色，用于线框/边线/高亮）
     - 新顶点：LineVertex { position: [f32;3] } (12 bytes)
     - 新建文件：crates/rc3d-render/src/pipelines.rs, shaders/flat_color.wgsl

     ┌────────────────┬──────────────┬─────────────┬────────────┬────────────┐
     │      管线      │     拓扑     │ PolygonMode │ DepthWrite │   Blend    │
     ├────────────────┼──────────────┼─────────────┼────────────┼────────────┤
     │ solid          │ TriangleList │ Fill        │ ON         │ Replace    │
     ├────────────────┼──────────────┼─────────────┼────────────┼────────────┤

     │ selection_fill │ TriangleList │ Fill        │ OFF        │ Additive   │
     ├────────────────┼──────────────┼─────────────┼────────────┼────────────┤
     │ selection_edge │ LineList     │ Fill        │ OFF        │ Additive   │
     └────────────────┴──────────────┴─────────────┴────────────┴────────────┘

     A4. 渲染 Pass 架构 — 三层合成
     - Pass 1: Solid（填充深度 + 着色）
     - Pass 2: Edge Overlay（深度测试不写入，绘制边线）
     - Pass 3: Selection（加色混合绘制选中元素）
     - 新数据结构：RenderObject { mesh_id, mvp, material, display_mode, 
     selected_faces/edges }
     - RenderFrame { solid_objects, edge_overlay_objects, selection_faces/edges,
      ... }

     A5. 显示模式系统
     - DisplayMode 枚举：Shaded / Wireframe / ShadedWithEdges / HiddenLine
     - HiddenLine
     实现：先画实体填深度（不写颜色），再画线框（深度测试剔除隐藏线）
     - 在 NodeEntry 加 display_mode: Option<DisplayMode>
     - App 快捷键：W=线框, S=实体, E=实体+边线, H=隐藏线
     - 新建文件：crates/rc3d-core/src/display.rs

     A6. 视锥剔除 — 已有 Frustum/Aabb，接入渲染
     - 在 RenderCollector 遍历时，计算世界空间 AABB，与 Frustum 求交
     - 被剔除的对象跳过，GPU 缓冲区保留但不提交 draw call

     修改的关键文件：
     - crates/rc3d-render/src/render_action.rs — 重构核心：用 TriangleMesh +
     MeshId 替代 Vec

     - crates/rc3d-scene/src/node_data.rs — 新增 TriangleMeshNode 变体
     - crates/rc3d-scene/src/node_entry.rs — 新增 display_mode 字段
     - crates/rc3d-render/src/vertex.rs — 新增 LineVertex，扩展 SceneUniforms
